About — Scope, Assumptions & Limitations

What the engine is for, what it calculates and on what basis, what it does not do, and who is responsible for the results. Read this page before you use the engine on a real structure.

Overview

ts-structural-eng-tools is an open-source, headless structural analysis and design engine written in TypeScript. It has three parts:

  • Analysis (fea): linear-elastic 3D analysis of frames, shells or both by the direct stiffness method, for user-defined load cases and factored load combinations.
  • Reinforced-concrete design (rc): flexural and shear capacity of rectangular RC beam sections per ACI 318-19, stirrup checks and rebar layout.
  • Strengthening (strengthening): steel-plate jacketing for flexure, side plates for shear, and the bolting between plate and concrete.

It is meant to be installed by front-end applications (web apps, desktop tools, scripts) as their calculation core. The front end builds a model from its own interface, calls the engine, and draws the results. Structural engineers can also call it directly from code to script and check calculations.

The source code is public and published under the ISC licence, so every formula behind a result can be read and checked. The theory notes explain the formulations, and the verification status says how they have been checked so far.

Responsibility and intended use

A structural calculation that is wrong can cost lives, injuries and money. The engine is a calculation aid. It does not replace the judgement of a qualified engineer, and it has not been certified by any authority.

⚠️ The engineer responsible for the design is responsible for every result taken from this engine. That covers choosing a suitable model, entering correct input, reading the warnings, checking the results against hand calculations or independent software, and confirming that the design meets the codes and regulations of the place where it will be built. The software is provided "as is", without warranty of any kind; see the ISC licence in the repository.

In practice this means:

  • Know the basis. Each result follows the assumptions on this page and on its theory page. Results from a model that breaks those assumptions (large displacements, material nonlinearity, dynamic response, a section shape that is not supported) are not valid, even when the engine returns numbers.
  • Read every warning. A warning means the calculation is valid but a code provision, a modelling assumption or a detailing rule needs attention. Warnings cite the clause they come from.
  • Errors are deliberate. When the assumptions of a calculation fail (a section that is not tension-controlled, an unstable structure), the engine throws an error rather than return a result it cannot stand behind. Do not work around an error to get a number.
  • Check independently. Before a result is used for design or construction, check the governing values with an independent method. Pay particular attention to the first models you build and to model types you have not checked before.
  • One design code. Design checks follow ACI 318-19 in SI units. Where another code applies, the design checks do not apply as they stand. The analysis results do not depend on a design code.
⚠️ Applications that embed the engine should show its warnings and errors to their users and point them to this page, so the people who see the results also see the basis and the limits.

The package does the structural engineering and nothing else. It never draws, stores a project or chooses units for display.

Assumptions

Every result rests on the following assumptions. A model that breaks one of them needs a different tool or a separate check.

TopicAssumption
MaterialLinear elastic and isotropic. No cracking, yielding, creep or shrinkage in the analysis; cracked stiffness enters only through section properties and modifiers that you choose.
GeometrySmall displacements and rotations: equilibrium is written on the undeformed shape, so there is no P-Δ or P-δ effect.
LoadingStatic. Loads are applied at once, with no inertia, damping or load history.
SuperpositionEvery result is linear in the loads, so a combination is exactly the factored sum of its load cases.
MembersStraight, prismatic, Euler–Bernoulli beams: plane sections stay plane and normal to the axis, and shear deformation is ignored. Torsion is uniform (Saint-Venant), with no warping. The member axis passes through the shear centre and the centroid.
ConnectionsRigid joints unless a release or a spring is given. Joint size is ignored (no rigid end zones yet).
ShellsFlat four-node facets with thin-plate (Kirchhoff) bending. Transverse shear deformation is ignored, which suits slabs and walls of ordinary span-to-thickness ratios.
SupportsFixed or linear springs, active in both directions.
UnitsSI, implicit in the numbers: mm, mm², MPa, kN, kN·m, kN/m. No unit conversion takes place inside the engine.
DesignACI 318-19 (SI) for RC beams. Strengthening functions say on each export which clauses are code and which are engineering models.
Limitations

These are the things most likely to matter on a real project. Each theory page also lists its own limitations and the points that are still open for review.

Analysis
  • No second-order analysis. P-Δ and member P-δ effects are not included. For sway frames and slender columns, apply moment magnification or a second-order analysis outside the engine.
  • No dynamics. There is no modal or response-spectrum analysis. Seismic and dynamic wind loads must be found elsewhere and entered as static load cases.
  • No diaphragm constraint. Floors act as rigid diaphragms only through the stiffness you model (shells or bracing). Null areas carry load but add no in-plane stiffness.
  • No shear deformation in members. Deep beams, short coupling beams and squat walls modelled as members are stiffer than in reality.
  • Mesh dependence. Shell results near point loads, column supports and re-entrant corners depend on the mesh. Refine it and check that the governing values converge.
  • Meshed plate and membrane areas are an interim solution. The translations they do not resist are held at generated mesh nodes and listed in autoRestrainedTranslations. Those zeros are not real displacements, so leave them out of deformed shapes. Under gravity, a plate with even a tiny slope or warp is rejected (332), and a larger warp can fail as unstable (304). A flat membrane with members along all four edges passes gravity to them by tributary area, with a warning. Without members on every edge, or if it is not flat, a meshed membrane under gravity is rejected (332) and one with no interior node keeps the load at its nodes, with a warning. Your own nodes still need restraints (328). Use type "shell" for these cases, or a null area for a slab that only passes load to its beams. Current behaviour, case by case →
  • Envelope only over combinations. The envelope covers the combinations in the model. Live-load patterning must be set up as separate load cases and combinations.
RC design
  • Rectangular, tension-controlled beam sections only. Columns, flanged sections and sections in the transition zone are not designed; the last throw error 102.
  • Section checks, not member design. Flexure and shear are checked at a section. Torsion, deflection, crack width, bar development and splices, and seismic detailing are not checked.
  • Simplified concrete shear strength. Vc uses the simplified expression of ACI 318-19 Table 22.5.5.1 for every section. That table also has an expression for members with less than the minimum shear reinforcement, which includes the size effect and the reinforcement ratio and can give a lower Vc; see the points for review.
Strengthening
  • Engineering models. ACI 318-19 has no provisions for bonded or bolted steel plates. The jacketing and side-plate methods are engineering models: confirm them against test data or a specialist review before relying on them.
  • Not checked: plate debonding and end peeling, buckling of compression plates between bolts, concrete breakout and pryout of anchors, the condition of the existing structure, and the load already on the member when the plates are installed.
Verification status

The engine is checked by an automated test suite (pnpm run test), which runs on every change. The tests compare results with closed-form solutions (for example fixed-end moments, cantilever and simply supported deflections, and slope-deflection results for semi-rigid ends), with independent oracles (the same structure modelled with subdivided members), with statics (reactions against applied loads), and, for shells, with standard benchmark problems. Each theory page lists the checks that apply to it.

⚠️ A consolidated verification report is in preparation. It will list each benchmark problem with its published source, the reference value, the engine's value and the difference, with the numbers produced by running the suite. Until it is published, rely on the checks described on each theory page and on your own independent checks.

Reporting a problem

If a result looks wrong, please open an issue at github.com/theerapat-s28/ts-structural-eng/issues. A report that can be reproduced gets fixed fastest: include the package version, the model or input as JSON, the result you got, the result you expected, and where the expected value comes from (a hand calculation, a textbook problem or another program).

Corrections to the theory notes, such as a wrong clause number, are just as welcome.
