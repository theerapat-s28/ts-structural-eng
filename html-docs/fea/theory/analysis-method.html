Analysis Method — Theory Notes

How analyze turns a model of members and shells into displacements, reactions and forces: the direct stiffness method, the supports, the sparse solver, the stability checks, and the superposition behind load combinations and envelopes.

⚠️ A calculation aid, not a substitute for engineering judgement. Results must be checked and accepted by the qualified engineer responsible for the design. Scope, assumptions and limitations →
Overview

The engine analyses the whole model, members and shells together, by the direct stiffness method. Each element contributes a stiffness matrix in global axes; these are added into one structure stiffness matrix K, the supports remove or stiffen degrees of freedom, and the equilibrium equations K·U = F are solved for the displacements U of each load case. Everything else (reactions, end forces, diagrams, shell forces) is recovered from U.

The element formulations are on their own pages: Frame element and Shell element. This page covers what happens at the level of the structure.

ℹ️ The basis is the finite element method and numerical linear algebra, not a code provision FEM. The formulas are read from src/fea/analysis/ and src/utils/skyline.ts; the checks quoted are in tests/fea/.

Steps solver/analyze.ts
1
Validate
Every input is checked first (validateModel): ids, references, finite numbers, allowed options, geometry. All problems are reported together, each with details that locate it. Nothing is analysed if one is found.
2
Expand the model
Shell areas are meshed into elements, members are connected to the nodes lying on them, and line restraints are spread to the nodes along each line.
3
Build and factorise the system once
Element stiffnesses are assembled into K in skyline storage, springs and held rotations are added, and K is factorised as UTU. The factor serves every load case.
4
Solve each load case
The load vector is formed from nodal loads, member loads, area loads and self-weight, and solved by forward and back substitution. Reactions, end forces and shell forces are recovered, unrounded.
5
Form the combinations
Each combination is the factored sum of the unrounded load-case solutions; its member diagrams are rebuilt from the combined forces.
6
Present
Results are converted to kN, kN·m, mm and rad, rounded, checked for global equilibrium, and the envelope over the combinations is taken.
Equilibrium equations

Each node has six degrees of freedom in global axes, in the order ux, uy, uz, rx, ry, rz, so global DOF 6n + k belongs to node n. With the element stiffnesses Ke and the element DOF maps:

K = Σe Ke,   K · U = Fassembled over members and shells

Splitting the DOFs into free (f) and fixed (s) ones, with no prescribed displacement at the fixed DOFs:

KffKfsKsfKss Uf0 = FfFs + Rs   ⇒   Kff Uf = Ff,   Rs = Ksf Uf − Fs

Only Kff, including the springs, is stored and factorised. The fixed DOFs get no equation number, so they never enter the solver; this is exact, unlike a large-number penalty.

Model expansion mesh/expand-model.ts
  • Shell meshing. Each shell area is divided into four-node elements, matched along shared edges so that neighbouring areas and the members along them share nodes. The generated nodes are listed in result.mesh; see Shell element.
  • Members through nodes. A member is connected to every node lying on it between its ends and is analysed as a chain of pieces; see Frame element.
  • Line restraints (lineRestraints) fix the chosen DOFs at every node on the segment between two nodes, generated mesh nodes included, for example a wall base fixed along its length. Combined with a point restraint at the same node, a fixed DOF stays fixed.
Supports and springs shared/solver/boundary-conditions.ts

Each restraint DOF is true (fixed), a positive number (a spring) or absent (free):

ValueEffect on the systemUnit of the spring
trueThe DOF is removed from the equations (U = 0) and gets a reaction—
number > 0The stiffness is added to the diagonal of Kff; the DOF stays free and gets a reaction equal to the spring forcekN/mm (translations), kN·m/rad (rotations)
absent, false or 0Free—

Springs are converted to N/mm (× 10³) and N·mm/rad (× 10⁶) before assembly. Supports act along the global axes and in both directions; skewed supports and support settlement are not yet available.

Assembly solver/analysis-system.ts

Every element that adds stiffness is treated alike: the nodes it connects and its 6n × 6n stiffness in global axes (StiffnessElement). A member is a 2-node element with Ke = TTk*T; a shell is a 4-node element. For every pair of element DOFs (a, b) that are both free, Ke[a][b] is added to Kff at the equation numbers of a and b. Only the upper triangle is stored, since K is symmetric.

Null areas add no stiffness and no DOFs: they only produce member loads (below).

Node ordering utils/skyline.ts

The cost of the factorisation depends on how far each equation reaches from the diagonal, and that depends on the order of the nodes. The engine numbers the nodes in reverse Cuthill–McKee (RCM) order of the node connectivity graph (two nodes are neighbours when an element joins them):

  1. For each connected part of the graph, start from a pseudo-peripheral node: run a breadth-first search, move to the farthest node of lowest degree, and repeat while the depth still grows (at most 8 times).
  2. Number the nodes breadth-first from that start, visiting the neighbours of each node in order of increasing degree.
  3. Reverse the whole order.

The six DOFs of each node then take consecutive equation numbers, skipping the fixed ones. The ordering changes only the work and memory, never the result. The stored size is reported as calculationDetails.profileSize.

Skyline storage and Cholesky factorisation

Column j of the upper triangle is stored from its first nonzero row fj down to the diagonal (the skyline, or column profile). fj is the lowest equation number among all the elements that touch equation j. No dense n × n matrix is ever built. Kff is symmetric positive definite for a stable structure and is factorised in place as

Kff = UT U,   U upper triangular with the same profile
Uij = Kij − Σk Uki UkjUii (i < j),   Ujj = √( Kjj − Σk<j Ukj² )

The sums run only over rows inside both columns' profiles, since entries above a profile stay zero in the factor. Each load case is then two triangular solves, UTy = Ff and U·Uf = y, so adding load cases costs little once the factor exists.

Stability checks

A structure that can move without resistance (a mechanism) has a singular Kff. The engine finds it in three places and reports where:

CheckTestResult
Pivot of the factorisationThe pivot Kjj − Σ Ukj² is at or below SINGULARITY_TOLERANCE (10⁻⁹) times its own diagonal term KjjFeaError 304, with the node and DOF of that equation
Translation at a node connected only to shellsA null direction of the node's 3 × 3 translational stiffness (for example the out-of-plane direction of a membrane)FeaError 328, with the node, shell and DOF
Joint rotation that nothing resistsA null direction of the node's 3 × 3 rotational stiffnessHeld by a spring that carries no force (below), listed in calculationDetails.autoRestrainedDofs

The node and DOF reported for error 304 are the equation where the factorisation failed; the mechanism involves that DOF, but may involve others too.

Unresisted joint rotations shared/solver/auto-restraint.ts

At a pin-jointed truss joint, or wherever every member releases the same rotation, the joint's rotation has no stiffness. The structure is still stable, but Kff is singular. The engine finds such rotations and holds them:

  1. For each node, add the 3 × 3 rotational blocks of every element meeting there, plus any rotational springs, over the free rotations: B.
  2. Decompose B by cyclic Jacobi rotations. Every eigenvector n whose eigenvalue is at or below 10⁻⁹ times the largest diagonal term of B is a null direction.
  3. Add k·n·nT to the node's rotations, with k the largest diagonal term (or the largest in the model when B is zero).

Each element stiffness is positive semi-definite, so nTBn = 0 means that the whole stiffness column of n is zero. The rotation along n is then decoupled from every other DOF, and the spring carries no force, so the results are unchanged. A load with a moment along n has no load path and throws FeaError 304 for that load case.

Load vector solver/load-case-solver.ts

For each load case, the global load vector F (N and N·mm) is the sum of:

  • Nodal loads: forces × 10³ and moments × 10⁶ at the node's DOFs.
  • Member loads and member self-weight: the equivalent nodal loads −TTf*fixed of each member piece, from the condensed fixed-end forces (Frame element).
  • Area loads on shells and shell self-weight: forces at the element corners (Shell element).
  • Area loads on null areas: first turned into member loads, then treated as member loads.

Each load names its load case, so a case is solved from exactly the loads tagged with it. A load case without loads gives zero results.

Null areas frame/area/area-member-loads.ts

A null area carries an area load (kN/m²) to the members along its edges and does nothing else. It is a load distribution, done before the analysis, not an element:

DistributionRuleWhat the edge members receive
twoWayEach point of the area goes to the nearest edge, so the area is split along the corner bisectorsA rectangle gives trapezoids on the long edges and triangles on the short, peaking at q·Lshort/2
oneWayStrips span between the support edges, parallel to the unsupported edges, and send half their load to each endA rectangle on its long edges gives q·L/2 on each
cantileverThe whole area goes to one support edgeA line load q·c and a torque q·c²/2 per unit length, with c the depth from the edge

The line load along each edge is the tributary width times q. The width is linear between the polygon's vertices, so the resulting trapezoidal member loads are exact for the chosen rule. The FEA reference has the geometry rules and distributeAreaLoads shows the member loads of a model.

⚠️ A null area adds no in-plane stiffness: it does not tie the edge members together and does not act as a diaphragm. Lateral loads need a lateral system in the model.
Solve and recover

After Uf = Kff⁻¹Ff (by the two triangular solves), the remaining quantities follow without further solving:

fmember = k* · T · Ue + f*fixedend forces of each member piece, local axes
R = (Σe Ke Ue) − F at every restrained DOF (fixed or spring), 0 elsewhere

K·U is summed from the element forces, without the support springs, so at a spring DOF R is the force in the spring. Shell forces are recovered element by element from the element displacements (Shell element). All of these are kept unrounded, in N and mm, as the state of the load case.

Global equilibrium check post/present-state.ts

Every load case and combination is checked: the applied loads F (including the equivalent nodal loads) plus the reactions R must have no resultant force and no resultant moment about the origin.

rF = | Σn (Fn + Rn) |,   rM = | Σn (Mn + xn × (Fn + Rn)) |

A warning is added when rF exceeds EQUILIBRIUM_TOLERANCE (10⁻⁶) times the sum of the absolute applied nodal forces, or rM exceeds the same times the largest node distance from the origin. The residual is always reported as equilibriumResidual. A warning points to an ill-conditioned stiffness, typically from very different stiffnesses side by side (a very stiff spring on a flexible member).

Load combinations solver/combinations.ts

A combination lists terms, each a load case or another combination with a factor. Nested combinations are expanded first into net factors αc on load cases (a loop throws FeaError 310). Because every result is linear in the loads, the combination is exact:

Scombo = Σc αc · ScS = U, R, F, member end forces, shell forces

The superposition is done on the unrounded states, so rounding errors do not accumulate. The member diagrams of a combination are not summed: they are rebuilt from the combined end forces and the factored member loads of all its cases, so their extremes are found exactly (Frame element). Combinations are linear only: an envelope-type combination is planned.

⚠️ Superposition holds only while every result is linear in the loads. The engine keeps it so by design: it has no tension-only members, gaps or other nonlinear behaviour. A future linearized P-Δ would fix the geometric stiffness from one named load set so that superposition still holds.
Envelope post/envelope.ts

When the model has combinations, result.envelope holds the maximum and minimum of each result over all of them, with the combination that governs each value: displacements and reactions per node, member diagram extremes with their position, and shell forces per element. When two combinations give the same value, the first one listed wins. Load cases are not part of the envelope; list them as single-term combinations if needed.

memberDemandEnvelope uses the same results to give the design demands of each member (the largest sagging and hogging M3, the largest |V2| and the governing N, each with the combination or case that produces it) for the rc capacity functions.

Units and rounding

The solver works in N and mm throughout. Results are converted to kN, kN·m, mm and rad only when they are presented, and rounded there: forces and moments to 4 decimals, displacements to 5 and rotations to 8. Every intermediate quantity, including the states that combinations superpose, stays unrounded.

Limitations
  • Linear static only. No P-Δ, no buckling, no modal or response-spectrum analysis, no time history. These are planned or outside the engine's basis; see the feature matrix.
  • No constraints. There are no rigid diaphragms, rigid links or equal-DOF constraints yet. A floor is rigid in its plane only if its modelled stiffness makes it so.
  • No prescribed displacements. Fixed DOFs are held at zero; support settlement is planned.
  • Conditioning. The solver works in double precision. Stiffness ratios beyond about 10⁹ between neighbouring elements can trigger the singularity test or the equilibrium warning. Use moderate spring values for "rigid" connections.
  • Memory. The skyline profile grows with the width of the model's node graph. Very large shell models can be slow in a browser; run them in a Web Worker and use diagrams: "extremes" to keep results small.
Points for review
  • Mechanism location. Error 304 names the equation where the factorisation failed. For a mechanism spread over several DOFs this may not be the DOF a user expects; a fuller diagnosis (the null vector) would help.
  • Equilibrium scale. The equilibrium tolerance is scaled by the applied nodal forces. A load case with moments only has a force scale of 1 N, so its check is stricter than intended.
