Frame Analysis

Linear-elastic 3D frame analysis by the direct stiffness method, run for user-defined load cases and factored load combinations, with member loads, area loads on null areas, self-weight, end releases, spring supports, force diagrams, envelopes and design demands that feed the RC capacity functions.

Overview

analyzeFrame takes nodes, members, supports, the load cases (dead, superimposed dead, live, wind…) and the load combinations built from them. It analyses every load case, forms every combination by superposition, and returns displacements, reactions, member end forces and force diagrams for each, plus an envelope over the combinations. Section properties come from rectBeamToSectionProperties or are supplied directly, so the module itself does not depend on the RC code.

ℹ️ This is a first-principles structural analysis, not a code provision, so its exports carry a Matrix analysis badge. Only the stiffness modifiers in rectBeamToSectionProperties come from ACI 318-19. Load factors are entered by the user; the module does not generate code combinations.

Load cases & combinations

Every load sits in a load case. A case is analysed on its own, so its results show what that load alone does. A load combination is a factored sum of cases (and of other combinations), for example 1.2D + 1.6L. Load factors are always entered by the user.

1
Define the load cases with a string id such as "D", "SD", "L". The optional type ("dead", "superDead", "live", "roofLive", "snow", "wind", "seismic", "other") is a label only and does not change the analysis.
2
List the loads in the model's top-level nodalLoads, memberLoads and areaLoads, each tagged with the loadCase it belongs to. Keeping them out of loadCases keeps the case list short in a large model, and the loads stay flat tables that can come straight from a spreadsheet or database. Their order does not matter.
3
Add self-weight to a case with selfWeight: 1. Every member then carries selfWeight · unitWeight · A per unit length along global −Z, so each member's section needs a unitWeight (rectBeamToSectionProperties sets 24 kN/m³). Use unitWeight: 0 for a weightless member.
4
Define the combinations as lists of terms, each { case, factor } or { combination, factor }. A combination may reference combinations listed after it; loops are rejected (310). Factors may be negative, e.g. 0.9D − 1.0W for reversed wind.
5
Read the results by id: result.cases.D, result.combinations["1.2D+1.6L"], and result.envelope for the max/min over all combinations. Case and combination ids share one namespace and must be unique across both lists.
ℹ️ A combination's force diagram is rebuilt from the combined end forces and the factored member loads of all its cases, so its extremes are exact. They are not sums of case extremes, which would overestimate a peak whose position differs between cases.
ℹ️ Pattern live loading (checkerboard spans) needs no special input: define one live case per span and combine them.

How member loads enter the analysis

Each member load is turned into the exact fixed-end forces of a prismatic member (from the beam shape functions), adjusted for any end releases, and applied to the end nodes as equivalent nodal loads. The member's force diagrams are then built from its end forces plus the loads themselves, so a point load shows a shear jump (both sides are reported) and a partial load changes slope exactly where it starts and ends. Under a trapezoidal load the shear is a parabola and the moment a cubic; their extremes (including a shear peak where a load changes sign) are located exactly. A torque load makes the torsion T vary linearly along its loaded length; the member's twist is not reported.

⚠️ Throws FrameAnalysisError 308 if a point load lies outside 0 ≤ a ≤ L, or a uniform, trapezoidal or torque load does not satisfy 0 ≤ start < end ≤ L; 302 if a load names a node or member that is not in the model; 309 if its loadCase is not in loadCases.

Null areas area/

A null area is a 3- or 4-node area that exists only to carry an area load (kN/m²) to the members along its edges. It adds no stiffness, no degrees of freedom and no diaphragm: the area loads are turned into ordinary trapezoidal (and, for a cantilever, torque) member loads before the analysis, and the frame does the rest. Define the areas in areas and their loads in areaLoads; distributeAreaLoads shows the member loads an area produces.

One-way areas

The span direction is not entered: it is the direction of the edges that are not in supportEdges, which must all be parallel so that no strip ends on an unsupported edge. A strip meeting a support at an angle θ spreads its half over a longer length, so a support receives chord / 2 · sin θ per unit length. The load keeps its resultant: it adds up to q·A acting at the area's centroid.

Cantilever areas

A cantilever area must be a rectangle, so its depth c is constant along the support. The support edge receives a uniform q·c and a uniform torque q·c²/2 about its axis; the torque's sign follows each member's own local 1 axis. The beam must be able to carry the torque — check its torsional stiffness J and end conditions. Only the load's normal part twists the edge, so a load with a component along the support edge is rejected (317): it would also bend the beam in its own plane. Gravity on a horizontal balcony, a normal load, and a ramp whose support edge is level are all fine.

Plotting on the model
1
Place each station at start + (x / length) · (end − start) along the member.
2
Offset it perpendicular to the member by the diagram value times a drawing scale: M3 and V2 along local 2, M2 and V3 along local 3. memberAxes returns those directions.
3
Choose the sign convention to draw. M3 is positive for sagging when local 2 points up, so it plots upward on a beam along X; to draw moments on the tension side, flip the sign. V2 is the force on the positive face, negative at the left support of a gravity-loaded beam; flip it for the textbook shear sign.
4
Deflected shape: add (ux, uy, uz) times a magnification factor to each station's position.
ℹ️ Values between stations follow the exact curves: under a uniform load the moment is a parabola and the deflection a quartic (a cubic moment and a quintic deflection under a trapezoidal load). Straight lines through the default 21 stations are close; the peak moment is always a station, and the deflection extremes are found on a 40-interval grid and then refined. At a hinged member end the member's own rotation is used, so the curve kinks there correctly even though the node does not rotate.
Using in a frontend

The module is plain TypeScript with no runtime dependencies or Node.js APIs, and both the model and the result are plain JSON data, so it runs in a browser, in a Web Worker, or on a server.

1
Import from @theerapat-s28/ts-structural-eng-tools/fea. The package ships an ES-module build (import) for bundlers such as Vite, with "sideEffects": false so unused code is dropped, and a CommonJS build (require) for Node.js.
2
Validate while editing with validateFrameModel and mark each issue's details (node, member, area and edge, load case, combination, field) in the UI.
3
Analyse in a Web Worker so the page stays responsive: post the model in, post the result out (structured-clone copies plain data).
4
Keep results small for large models with diagrams: "extremes", and keep the createFrameAnalysis object in the worker to answer "show this member's diagram" requests.
5
Show errors in place: a thrown FrameAnalysisError has code, details and issues; a 304 (unstable) names a node and DOF of the mechanism.
TypeScript — worker.ts
import { createFrameAnalysis, type FrameAnalysis } from "@theerapat-s28/ts-structural-eng-tools/fea";

let analysis: FrameAnalysis | undefined;
self.onmessage = ({ data }) => {
  try {
    if (data.type === "analyse") {
      analysis = createFrameAnalysis(data.model, { diagrams: "extremes" });
      self.postMessage({ type: "result", result: analysis.result });
    } else if (data.type === "diagram" && analysis) {
      self.postMessage({ type: "diagram", diagram: analysis.memberDiagram(data.resultId, data.memberId) });
    }
  } catch (e) {
    self.postMessage({ type: "error", code: e.code, message: e.message, issues: e.issues });
  }
};

Analysis flow
1
Validate the model, load cases, loads and combinations with validateFrameModel (errors 301–303 and 305–317); every problem is collected, and the first is thrown with all of them in issues.
2
Distribute area loads: each null area's edge profiles are built once for a unit load, then scaled for each area load and cut at the members along the edges, giving trapezoidal (and cantilever torque) member loads in their load cases — what distributeAreaLoads returns.
3
Build the system once: member local stiffness, end-release condensation and transformation T; number the free DOFs with the nodes in reverse Cuthill–McKee order (which narrows the band), assemble the stiffness in skyline (variable-band) storage, add spring stiffnesses and factorise by Cholesky once. A singular matrix throws 304, naming a node and DOF of the mechanism.
4
Solve each load case against that factorisation: group the loads by their loadCase, resolve member loads and self-weight into local fixed-end forces, form F = nodal loads − fixed-end forces, and recover displacements, reactions R = K·U − F and member end forces.
5
Combine: expand nested combinations into net case factors and superpose the unrounded case results; rebuild each combination's diagrams exactly.
6
Check and present: global force and moment equilibrium of each case and combination, rounding of presented values, and the envelope over all combinations.
